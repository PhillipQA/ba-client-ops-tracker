# v0.6.48 — One-run database setup for fresh deployments

## New installation

Open `database/setup.sql`, paste the entire file into a new Supabase project's SQL Editor, and click Run once. It includes all 14 schema versions in order, including Gmail account configuration and persistent label names, with one transaction covering the entire installation.

The script creates all 29 application tables, indexes, database functions, initial Internal Admin and BXI-Core account placeholders, and current row security and server permissions. Fresh BXI-Core has the current module list, including Requirements & Traceability. Bootstrap passwords are supplied privately through the app server environment, not embedded in SQL.

See `database/README.md` and `docs/setup/deploy-new-server.md` for the complete setup and environment instructions. The full build and a separate identical SQL download are provided.

## Existing installation

A working v0.6.47 installation needs **no SQL changes** for this release. Do not run fresh setup against an existing database. It checks for any existing application table and stops before changes, including when it finds a partial installation.

If you move the app server but keep the same Supabase project, no database SQL is required. If you move the data to another Supabase project, restore a backup and storage files, preserving the integration master key; the fresh setup does not copy data or credentials.

The historical `database/migrations/` files remain available for incremental upgrades and previous release notes. New installations only need `database/setup.sql`.

## Patch from v0.6.47

```powershell
npm run patch -- "E:\Playwright\ba-client-ops-patch-v0.6.48-single-database-setup.zip"
npm run build
npm run patch:status
```

No new application dependencies or environment variables are introduced. Future schema changes should regenerate the setup with `npm run db:bundle`; `npm run db:check` detects drift from the migration sources. Neither command contacts a database.
