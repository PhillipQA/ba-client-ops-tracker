# v0.6.41 — Document Agent AI-assisted RTM

This release extends v0.6.40 with a Manual / AI-assisted entry switch. Users can bring their own BRD, FSD and test-case documents, review a proposed requirement/reference map, then add selected rows to an existing RTM.

## Which AI is used?

The existing **Document Agent** from **Account Settings → AI Agent Manager**. Its account-specific provider, model and encrypted credential are reused through the existing AI adapter. RTM does not hardcode a model, use BA Assistant credentials, or require another API key. The import dialog displays the active provider/model before transmission. Enable/configure the Document Agent if it is not already available. Model capabilities, availability, cost and quota depend on that provider and account.

## Upgrade from v0.6.40

1. Back up source and tenant data, stop the local app, and confirm `npm run patch:status` reports **0.6.40**. If still on 0.6.39, install the v0.6.40 Requirements & Traceability patch first.
2. Save **the patch ZIP**, not the full-build ZIP, to `E:\Playwright`. From `E:\Playwright\ba-client-ops-tracker`, run:

```powershell
npm run patch -- "E:\Playwright\ba-client-ops-patch-v0.6.41-document-agent-rtm.zip"
npm run build
npm run patch:status
```

3. Restart with `npm run dev`, or commit/push through your existing Render deployment process. Production uses `npm start` after building. Refresh old browser tabs.
4. Requirements & Traceability must be enabled for the tenant and user. Administrators/Contributors with module write access can generate and accept mappings. Viewers cannot generate/import. RTM-only writers do not need Tasks access to import references; ordinary task-link permissions remain unchanged.

No new dependencies, environment variables or SQL migrations are introduced. Existing v0.6.40 persistence and AI Agent Manager setup must already work. Keep existing environment files. New installations using the full source ZIP still require the normal setup, `npm ci` and `npm run build`.

## Workflow

1. Create or open a client/project-specific RTM.
2. Choose **AI-assisted → Add from documents**. Switch back to Manual at any time for manual rows or structured CSV/XLSX import.
3. Select BRD, FSD or Test cases, then upload one or more documents. Files do not have to be generated by this app. Each source can be reclassified or its extracted text corrected. Pasted source text is also supported.
4. Review the extracted content. Confirm that the sources belong to this RTM's client/project and may be sent to the displayed Document Agent provider/model. Only clicking Generate mapping preview starts AI usage.
5. Review proposed requirements, parent/child structure, reference mappings, source excerpts, gaps and conflicts. No rows are saved by generation. Select the rows you want, edit new-row titles/details/priority/parent as needed, and confirm review.
6. Choose **Create new requirement**, or **Add references to** an existing requirement. The latter appends evidence and Documentation/FSD/Testing reference fields only; it does not replace the existing requirement's title, details, parent, priority, statuses, overrides or task links. Possible duplicate titles/references are shown. Exact duplicate new titles are blocked.
7. Add the reviewed rows. The application allocates permanent requirement IDs. Open Documentation, FSD or Testing to see saved **Document source evidence**. Existing rows receiving new evidence are flagged for impact review through the normal RTM history/revision rules.
8. Users create/link/assign Tasks and Subtasks themselves. Once linked, the existing deterministic RTM status calculation continues as before.

## Mapping and safety rules

- BRD evidence maps to Documentation; FSD evidence to FSD; test-case evidence to Testing. References preserve real source codes/sections or use the filename when no code is available.
- Test cases are coverage references, not proof of execution. New stage statuses all start at **Not Started**, even when source text mentions Passed or Approved. Existing statuses never change because of an AI import.
- Document Agent cannot create tasks, link work, assign people, sign off work, or change completion status in this flow.
- Every proposal must contain a quotation verified against its supplied extracted source. Unknown source IDs, unverified quotes, foreign requirement IDs and invalid hierarchies are rejected. Unsupported section/code strings are removed and flagged for review. Quote matching normalizes whitespace and letter case; it is not independent factual verification.
- Semantic mapping is still AI judgment: users must check it. Test-case-only inferred requirements are flagged. The preview lists missing coverage and contradictions; AI completeness is not guaranteed. No automatic document-version diff is included.
- Only this authenticated tenant's selected RTM and uploaded source text are supplied. Other matrices, tasks, user lists and assignees are not sent.
- Provider/model changes require refreshed destination consent. Stale matrix revisions require a new preview. Failed requests preserve the open draft and do not save rows. No automatic AI retry is performed because retries may incur charges.

## File and scope limits

- PDF, DOCX, TXT, MD, CSV and JSON: up to 10 MB per file. Convert old DOC/XLS formats first.
- XLSX: up to 5 MB, 30 worksheets and 30 MB expanded XML. All worksheets, including hidden ones, are extracted and labeled. Review/remove sensitive text before consent. Formulas are not executed; cached cell values are read when present. Macros and external workbook links are not fetched.
- PDFs: up to 80 pages. Scanned pages use the existing browser-side English OCR. Diagrams, embedded images and handwritten/poor scans are not reliably interpreted; verify extraction and mapping.
- Up to 12 sources; 120,000 characters per source; 180,000 source characters total.
- Up to 80 proposed rows per request. Split large documents into focused batches. Large existing RTM context (over 200,000 serialized characters) is rejected instead of silently truncated wholesale; each existing requirement contributes its title and first 600 description characters.
- The existing 2,000-requirement RTM limit remains. A proposal has at most 20 evidence entries; a saved requirement supports 100. Stage reference fields retain their 2,000-character limit.

## Privacy and persistence

Original uploaded files are read in the browser and are not archived by this feature. Extracted text, the selected RTM's existing requirement summaries and its client/project names are sent through the application server to the configured Document Agent provider. API credentials stay server-side. Provider usage charges and retention rules apply.

Accepted requirements, references and source excerpts are saved in the existing tenant snapshot and recorded in RTM activity history. Full original files and full extracted sources are not retained there. Existing Excel/CSV exports include the mapped stage reference fields; they do not include the full source-evidence excerpts.

The unsaved AI draft exists only while the dialog remains open. Closing or refreshing discards it after a warning. There is no resumable background import or cross-device draft synchronization in this release.

## Validation

See [verification-v0.6.41.md](verification-v0.6.41.md). AI-provider calls are simulated in local tests: model-specific mapping quality, live API quota/access, production Render/Supabase and Windows execution need staging validation with your own account.

## Rollback

Back up tenant data before rollback. `npm run patch:rollback`, rebuild and restart restores the prior code; it does not reverse imported requirements or provider usage. v0.6.40 does not display the added source-evidence fields. Reverting farther than v0.6.40 may discard RTM data when older code saves a workspace.
