# v1.0.2 — Help choosing the key column

**No database migration and no new setting.**

When you connect a tracker to a Google Sheet, the tracker matches Sheet rows to tracker rows by the **key column**. A row whose key is blank, or the same as an earlier row's, is left out. Before, the dialog did not say so: choosing a column such as Client could bring in only one row per client.

- The key column list shows, for each column, **"different on every row"** or how many rows it would keep (for example "Client — 2 of 320 rows").
- The best column is chosen for you: the first that is different on every row, or else the one that keeps the most rows.
- If the chosen column leaves rows out, a warning says how many rows would sync and why, and **Connect anyway** must be ticked to go ahead. Blank cells on heading or note rows are fine.

To fix a tracker that already came in with too few rows: **More → Stop syncing with the Sheet**, delete the tracker, and connect again with a column such as a ticket or Git number.

After the deploy, confirm **v1.0.2**, hard refresh (Ctrl+Shift+R), and try **Trackers → From Google Sheet**.
