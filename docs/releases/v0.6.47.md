# v0.6.47 — Persistent Gmail label names and message navigation

## Changes

- Gmail label names are saved in Supabase with each user's private communication settings. Refresh Gmail labels saves the names immediately, without requiring a message sync or Save my settings. Reloading the Hub loads the saved names.
- Existing connected users automatically retrieve and save missing names when the Hub opens after this upgrade. If Google's refresh fails, existing saved names remain available. Refresh Gmail labels updates renamed labels. System labels are excluded, matching the existing monitored-label behavior.
- A disconnected or different Gmail mailbox clears the saved label catalog. IDs remain the internal filter keys; the dropdown shows names, a loading indicator, or an unavailable-label description.
- Open message scrolls to and focuses the message details below the list, allowing for the sticky header. Opening the same message again also scrolls. Reduced-motion preferences are respected.
- Pagination starts at 5. Existing v0.6.46 page-size preferences reset to 5 once while preserving Cards/Rows. Later selections of 5, 10, or 15 are remembered per user in the browser.

## Upgrade from v0.6.46

1. Back up the app and database.
2. In Supabase SQL Editor, run `database/migrations/schema-v14-gmail-label-catalog.sql` after v13. This adds one JSON column to the existing private settings table; its current access rules still apply.
3. Stop the local app and apply the patch from the project folder:

```powershell
npm run patch -- "E:\Playwright\ba-client-ops-patch-v0.6.47-gmail-labels-navigation.zip"
npm run build
npm run patch:status
```

4. Restart or deploy the updated source to Render, then refresh the browser. No new environment variables, dependencies, or Google OAuth configuration are required.

The patch does not run the SQL migration for you. The full build includes v12, v13, and v14 migrations for installations that still need those prerequisites.
