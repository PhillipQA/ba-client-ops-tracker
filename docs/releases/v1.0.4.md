# v1.0.4 — Back and Forward work, every page has its own address

**No database migration and no new setting.**

The browser's Back button used to leave the app: switching pages changed the screen without telling the browser, so the history had only one entry. Now every page has a real address.

| Page | Address |
| --- | --- |
| My Action Center | `/` |
| Tasks | `/tasks` |
| Work Hub | `/work-hub` |
| Trackers / one tracker | `/trackers` / `/trackers/<id>` |
| One client / one project | `/clients/<id>` / `/projects/<id>` |
| Other pages | `/clients`, `/projects`, `/documents`, `/requirements`, `/reports`, `/ai`, `/settings`, `/users`, `/themes` |

- **Back and Forward** move between visited pages; Back from a tracker returns to the list.
- **Refresh** keeps your place; pages and trackers can be **bookmarked or shared**. Signed-out visitors sign in first, then land on the page.
- **Ctrl/⌘-click or middle-click** a sidebar item or tracker name opens it in a new tab.
- Tab titles name the page.

The built-in server already sends every page address to the app. If a proxy sits in front of it, make sure it does the same (only `/api` and `/assets` are special).

After the deploy, confirm **v1.0.4**, hard refresh (Ctrl+Shift+R), open a tracker and press the browser's Back button.
