# v0.6.42 — Settings polish and personal interface modes

Settings now has consistent card padding, borders, form spacing, button alignment, and responsive layouts. Appearance, Templates, AI Agents, and Integrations have separate tabs. Switching tabs keeps unsaved form entries during that visit.

## Choose an appearance

1. Open **Settings → Appearance → Interface mode**. You can also open **My Themes**, including users who do not have access to account Settings.
2. Choose **Dark**, **Light**, or **Gray**. The choice saves immediately to your own profile in the current account.
3. Continue working. Menus, panels, forms, tables, dialogs, and document editor controls use the selected colors. FSD document paper retains its white-page formatting.
4. Use **Use original theme appearance** to restore the appearance supplied by your existing background theme.

Existing users retain their original appearance until they choose a mode. Dark uses charcoal surfaces; Light uses white surfaces; Gray uses soft gray surfaces with dark text. A saved choice takes priority over the operating system's color preference.

Background themes remain a separate setting on the same page. Existing images, preset definitions, personal backgrounds, and client-specific background choices are preserved. Switching interface modes does not select a different background. Your interface choice applies across your clients; your existing client background overrides continue to apply.

Document template files and export generators are unchanged. Existing DRF uploads, FSD content and layout, test-case generation, and Sign-Off templates keep their current behavior. This release does not change RTM mapping, task/subtask assignments, or account permissions.

## Upgrade from v0.6.41

1. Back up your project and tenant data, stop the local app, and run `npm run patch:status`. This patch requires **0.6.41**. Apply the matching earlier patches first if you are on an older release.
2. Save **ba-client-ops-patch-v0.6.42-appearance.zip** to `E:\Playwright`. From `E:\Playwright\ba-client-ops-tracker`, run:

```powershell
npm run patch -- "E:\Playwright\ba-client-ops-patch-v0.6.42-appearance.zip"
npm run build
npm run patch:status
```

3. Restart with `npm run dev`, or commit and push the updated source through your existing Render deployment process. Production uses `npm start` after building. Refresh existing browser tabs.
4. Open Settings → Appearance and choose a mode.

Use the **patch ZIP** for `npm run patch`; it includes `patch-manifest.json`. The **full-build ZIP** is the complete source for a clean checkout and does not serve as a patch. For a clean checkout, preserve your environment configuration, run `npm ci`, then `npm run build` and start the app as usual.

No new dependencies, environment variables, or SQL migrations are required when upgrading from v0.6.41. The optional preference uses the existing tenant/user persistence. Account credentials and personal preferences retain their existing account boundaries.
